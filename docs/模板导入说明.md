# 给其他 Agent 使用的分块模板

打开工作台，中间“分块组装”上方点击 **按模板导入 → 复制给 Agent 的模板**，把内容和自己的生图需求一起发给任意 Agent。将返回的完整 JSON 复制回来，查看右侧预览，然后点 **导入为新方案**。

也可以直接把 [Agent 提示词模板.txt](Agent提示词模板.txt) 交给 Agent。[示例 JSON](prompt-blocks-template.example.json) 可以直接粘贴测试。两份文件与工具内置模板一致。

导入是本地格式解析，不使用 LLM、不调用翻译、不读取 API Key，不会根据句子猜测块类型。用户确认后创建一个新方案，不覆盖当前方案；同名方案自动加后缀，可以撤销。词库没有的标签也会保留。

## 固定结构

顶层必填 `format: "prompt-blocks-template"`、`version: 1`、`name`、`blocks`。可选 `characters`、`parameters`、`models`、`notes`、`autoIdentity`、`autoIntroduce`。字段名区分大小写，未知字段报错，不会静默丢弃。

| 内容 | 写法 | 导入位置 |
| --- | --- | --- |
| 标签块 | `type: "tags"`，正负面各一个数组 | 可单独编辑的标签 |
| 自然语言块 | `type: "prose"`，正负面各一个 `{ "zh": "", "en": "" }` | 中文原文与英文描述 |
| 角色 | `characters` 数组 | 当前新方案的“角色定义” |
| 参数 | `parameters` 对象 | 右侧配方参数 |
| 模型名 | `models` 对象 | 右侧模型信息 |

每块必填 `type` 和 `name`；`role` 省略时为“自由补充”。允许的 role：自由补充、公共基础、角色、服装、场景、光照、画师串、负面约束、完整组合。

标签示例：

```json
{
  "type": "tags",
  "name": "场景与光照",
  "role": "场景",
  "positive": ["library", {"text": "soft lighting", "label": "柔光", "weight": 1.1}],
  "negative": ["text", "watermark"],
  "weight": 1,
  "enabled": true
}
```

数组中每一项是一个标签；字符串内的逗号不会再次拆分，文本也不会被改写。需要多个标签就写多个数组项。权重用 `weight` 字段表示，不在字符串里内嵌 NAI/SD 权重语法。单词权重与整块权重相乘；默认都是 1，范围为 -20～20。词条也支持 `enabled`。

自然语言使用 `{{A}}`、`{{B}}` 等引用已定义角色。角色需包含 `alias`、`name`，可选 `gender`（unknown/female/male/other）、`identityTags`（英文标签数组）和 `description`（zh/en 对照）。代号统一为大写且不重复。中英文占位符出现次数需一致；只有中文也能导入，但会标为待翻译，不会自动生成英文。

自然语言段落完整保留，不按逗号拆词，不支持整段权重。标签块中的角色名称不会自动绑定到某个区域；角色定义仅用于占位符展开及自动补充身份、外貌。

参数允许 `width`、`height`、`steps`、`cfg`、`seed`、`denoise`、`sampler_name`、`scheduler`。模型允许 `unet_name`、`clip_name`、`vae_name`。不确定的字段省略，不能填 `null` 或虚构默认值。大于 JavaScript 安全整数范围的种子应使用十进制字符串，最大支持 `"18446744073709551615"`，避免导入时丢失精度。参数不会提交到 ComfyUI。

## 复制现有方案再交给 Agent

弹窗中点击 **复制当前方案模板**，可以让 Agent 基于你的现有方案修改。复制包含这个方案的角色、块、参数、模型名称及备注，不包含 API 设置或其他方案。中英文尚未同步时会要求先校对，以免把过期译文当成有效对应内容。

这里只接受完整 JSON 或单个 JSON 代码块。格式错误会给出字段位置，例如 `blocks[2].positive`；修正后才能导入。最多 100 个块、32 个角色、每侧 5,000 个标签、总文本 100 万字符。
